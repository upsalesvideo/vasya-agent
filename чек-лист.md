# Чек-лист проверки перед выдачей

Проходишь весь список сам. Результат каждого пункта пишешь в `проверка/отчёт.md`
(✅ / ✏️ поправил / ⚠️ заглушка). «Готово» без заполненного отчёта не бывает.

## 0. Запуск сайта в браузере

В `.claude/launch.json` рабочей папки есть (или добавляешь) конфигурация:

```json
{
  "name": "vasya-site",
  "runtimeExecutable": "python",
  "runtimeArgs": ["-m", "http.server", "8766", "--directory", "<vasya>/сайты/<slug>/site"],
  "port": 8766
}
```

Меняешь `<slug>` на текущий проект, затем `preview_start` с `name: "vasya-site"`.
Если сервер уже запущен на другой папке — `preview_stop`, потом заново.

## 1. Браузерная проверка — три ширины

Для каждой ширины: `resize_window` 1440×900 → 768×1024 → 375×812 (mobile preset),
перезагрузка страницы, затем:

| Проверка | Как | Норма |
|---|---|---|
| Ошибки | `read_console_messages` (onlyErrors) + `read_network_requests` | 0 ошибок, все ресурсы 200 |
| Горизонтальный скролл | `javascript_tool`: `document.documentElement.scrollWidth <= window.innerWidth` | true |
| Шрифты | `javascript_tool`: `[...document.fonts].map(f => f.family + ' ' + f.status)` | все `loaded`; заголовки и текст в заданных шрифтах, не в запасных |
| Кнопки ровные | `javascript_tool`: для всех `button, .btn, a[class*=btn]` собрать `getBoundingClientRect()`; в одном ряду (одинаковый `top`) — одинаковая `height`; текст не переносится в 2 строки, если не задумано | разница высот 0 px |
| Тап-цели | те же rect: `height >= 44 && width >= 44` на 375 px | все ≥ 44 |
| Переполнение текста | `javascript_tool`: элементы с `scrollWidth > clientWidth` | нет |
| Картинки | `img` без `alt`, с `naturalWidth === 0` | нет |
| Ссылки и кнопки | `read_page` (interactive): у каждой понятный текст и адрес; якоря ведут на существующие `id`; телефон `tel:`, мессенджер — рабочая ссылка | всё ведёт куда надо |
| Форма | `form_input` + клик по отправке: валидация, состояние «отправлено», ошибки на русском | работает или честно помечена «подключить» |
| Меню на мобильном | открывается, закрывается, ссылки внутри работают, скролл под ним заблокирован | да |
| Reduced motion | `javascript_tool`: `matchMedia('(prefers-reduced-motion: reduce)')`; в CSS есть блок, обнуляющий transition/animation | есть |
| Скриншоты | `computer` screenshot на каждой ширине, полная высота — прокруткой | сохранить в `проверка/1440.png`, `768.png`, `375.png` |

Смотришь скриншоты глазами: ничего не наехало, отступы ритмичные, hero читается за 3 секунды,
кнопка целевого действия — самый заметный элемент экрана.

## 2. Impeccable audit

`Skill impeccable` с аргументом `audit <путь к site/>`. Пять измерений: доступность,
производительность, темизация, адаптив, «сделал ИИ». Каждое замечание уровня Critical /
Important правишь сразу. Остальные — по здравому смыслу, что не поправил — в отчёт.

## 3. Impeccable polish

`Skill impeccable` с аргументом `polish <путь к site/>`, планка «flagship». Дизайн-система
для polish — `DESIGN.md` проекта. Правишь всё, что нашёл.

## 4. Аудит движения (Эмиль Ковальски)

`Skill design-motion-principles`, режим Audit, **с флагом `--terminal`** (без HTML-отчёта).
Взвешивание — то же, что на этапе E. Правишь: лишние анимации у частых действий,
длительности, изинги, отсутствие reduced-motion, анимацию layout-свойств.

## 5. Pre-Delivery Checklist UI/UX Pro Max

Из выдачи `--design-system` (лежит в `брифы/`), обычно:

- [ ] Нет эмодзи вместо иконок (inline SVG)
- [ ] `cursor: pointer` на всём кликабельном
- [ ] Hover-состояния с переходом 150–300 мс
- [ ] Контраст текста ≥ 4.5:1, кнопок ≥ 3:1
- [ ] Видимый фокус для клавиатуры
- [ ] `prefers-reduced-motion` учтён
- [ ] Адаптив: 375, 768, 1024, 1440

## 6. Повторная браузерная проверка

После правок пунктов 2–5 повторяешь пункт 1 целиком. Скриншоты перезаписываешь.

## 7. Содержание и конверсия

- [ ] `h1` — оффер: кому, что, какой результат. Понятен за 3 секунды без прокрутки.
- [ ] Кнопка целевого действия в hero, в середине, в конце; один текст, один цвет.
- [ ] Рядом с кнопкой — что произойдёт после (снимает страх).
- [ ] Ни одного выдуманного факта. Заглушки помечены «вставить настоящее».
- [ ] Контакты, реквизиты, политика — только те, что дал пользователь.
- [ ] Заголовки не повторяют текст под ними; нет «качественно», «индивидуальный подход», «команда профессионалов».
- [ ] `<title>` и `<meta name="description">` заполнены под оффер; `lang="ru"`; favicon есть или заглушка.
- [ ] Сайт открывается двойным щелчком по `index.html` без сервера (пути относительные).

## Если магазин (дополнительно к пунктам 1–7)

Запуск: конфигурация `vasya-shop` в `launch.json` — `python app.py` из папки `site/`,
порт 8767. Перед проверкой `seed.py` наполняет базу товарами владельца (или примерами с
пометкой «пример»).

Путь покупателя, на трёх ширинах:

- [ ] Каталог: категории и фильтры работают, карточки одной высоты, цена читается, фото не растянуты.
- [ ] Товар: галерея листается, варианты выбираются, «В корзину» меняет счётчик в шапке без перезагрузки.
- [ ] Корзина: количество меняется, удаление работает, итог пересчитывается, корзина переживает перезагрузку.
- [ ] Оформление: валидация полей на русском, способы доставки/оплаты из интервью, после отправки — страница «Спасибо» с номером заказа.
- [ ] Уведомление о заказе ушло туда, куда просил владелец (или заглушка помечена).

Админка:

- [ ] Вход по паролю; без входа `/admin` недоступна; выход работает.
- [ ] Товар: создать → появился на витрине; изменить цену и фото → изменилось на витрине; скрыть → пропал; удалить → пропал вместе с фото.
- [ ] Загрузка фото: до 10 МБ, jpg/png/webp, картинка сжимается до разумного размера.
- [ ] Заказы: новый заказ виден со всем содержимым и контактами, статус меняется.
- [ ] Настройки: контакты и тексты доставки/оплаты правятся и отображаются на витрине.
- [ ] Импорт из Excel (если есть): загрузил прайс → товары обновились, ошибки показаны построчно.
- [ ] Админка удобна с телефона (375): таблицы прокручиваются внутри себя, кнопки ≥ 44 px.

Техника:

- [ ] Пароль в базе хешем, секретный ключ Flask не в коде (файл `.env` / переменная).
- [ ] Загрузки только в `static/uploads`, имена файлов безопасные.
- [ ] `README.md` проекта: запуск, вход в админку, смена пароля, выкладка, подключение оплаты и уведомлений.

## Медиа (если есть сгенерированное или видео/музыка)

- [ ] Все картинки ≤ 200 КБ, `srcset` с `-800` версией, `width`/`height`, `alt` по-русски.
- [ ] Видео в шапке: `muted autoplay loop playsinline`, постер есть, ≤ 3 МБ, при reduced-motion не играет.
- [ ] Музыка не автоплеит; кнопка с подписью; ≤ 4 МБ.
- [ ] Фото людей и объекта — владельца, не сгенерированные «похожие»; сгенерированное помечено в README.
- [ ] `медиа/manifest.json` заполнен, в отчёте — потраченные кредиты.

## Право (любой сайт с формой, счётчиком или продажей) — по `право.md`

- [ ] `privacy.html`, `consent.html`, `cookies.html` (+ `offer.html` при продаже) есть, в стиле сайта, с версией и датой. `grep "\[указать" site/` — пусто, либо каждая заглушка названа в уведомлении владельцу (`право.md`).
- [ ] Подвал на каждой странице: реквизиты оператора (наименование, ИНН, ОГРН, адрес, e-mail) + ссылки на все документы + «Настройки cookie».
- [ ] Каждая форма: галочка согласия снята, `required`, ссылки на согласие и политику; кнопка неактивна без галочки; рассылка — отдельная необязательная галочка.
- [ ] Отправил тестовую заявку: в ней пришли `consent=1`, `consent_version`, `consent_at`, `page`, `marketing`.
- [ ] Cookie-баннер: показался при первом визите (чистый `localStorage`); «Только необходимые» → в `read_network_requests` нет `mc.yandex.ru`; «Принять все» → Метрика загрузилась; выбор пережил перезагрузку; ссылка в подвале открывает баннер снова.
- [ ] `read_network_requests` на всех страницах: нет запросов к `googleapis`, `gstatic`, `jsdelivr`, `unpkg`, `cdnjs`, `google-analytics`, `facebook`, `connect.facebook`. Шрифты из `assets/fonts/`.
- [ ] Поля формы — только нужные (имя + контакт), лишних нет.
- [ ] У кнопки покупки/заказа — фраза об акцепте оферты; в магазине на чекауте — галочка оферты.
- [ ] README проекта: уведомить Роскомнадзор (pd.rkn.gov.ru), назначить ответственного, где менять реквизиты, версии текстов согласия и cookies.
- [ ] Если остались заглушки — в выдаче и после выкладки отправлено «Уведомление владельцу» из `право.md` с точным списком, что прислать.
